# Interface translations

Beacon supports `en` and `zh-CN`. The saved `language` preference defaults to
`system`; unsupported system languages fall back to English. Explicit language
choices persist independently of other settings drafts. System preferences are
checked at startup and when a workspace or settings window becomes active.

Catalogs live in `crates/beacon-ui/locales/*.json`, grouped by feature. Each stable
key contains its English source and Simplified Chinese translation. Rust I18n
embeds these catalogs in the executable. The UI build checks missing languages,
duplicate keys, duplicate source text and matching `%{parameter}` names.

Use `i18n::message("resources.selected", &[("count", count.to_string())])` for
parameterized messages. Existing view models retain canonical English labels;
`i18n::text` resolves those labels through a generated catalog index **only at
the presentation boundary**. Reword a message by editing its existing key.
Context-dependent wording should use distinct keys and `message` directly.

Use `i18n::input` for reactive placeholders, `i18n::table` for cached column
headers, and `i18n::window_title` for native window titles. Language changes
update these views without rebuilding their state. Static translated strings
are cached; rendering does not read or parse catalog files.

Keep Kubernetes Kind names, API groups, resource identities, field paths, raw
errors, YAML, container logs, labels and annotations unchanged. Translate status
labels at the display boundary; filters, actions and saved column IDs must keep
their canonical values. User-entered names and values must bypass translation.

界面支持英文和简体中文，默认跟随系统；其他系统语言回退英文。新增文案需在对应功能的
JSON 文件中维护两种语言，使用稳定的 key 和完整句子模板。翻译仅用于显示层，资源名称、
原始数据、内部标识、筛选值和用户输入保持原样。
